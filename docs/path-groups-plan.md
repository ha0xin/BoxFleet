# Path 分组与组授权计划

日期：2026-10-18。本文记录最初的持续组授权方案；现已改为“组只作为单条权限的批量选择快捷方式”，实际行为见 [Path groups](path-groups.md)。以下仅保留历史设计依据。原状态：基础组授权已实现，见[使用说明与实际 API](path-groups.md)。本文保留设计依据；实际接口采用统一预览/变更入口，表结构、限额和行为以使用说明及源码为准。与[节点地址及出口策略计划](node-addresses-and-egress-plan.md)独立推进。

## 1. 产品行为

管理员建立“香港线路”“IPv6 线路”“高级套餐”等 Path 组，一次给用户授权一个组，用户获得组内所有可用线路。**组授权持续跟随成员变化，不是操作时复制一批单独授权。**

- 一个 Path 可以属于多个组，一个用户可以获授多个组。
- 保留单独 Path 授权；有效权限取所有有效来源的并集。
- 给组加入 Path，已有获授用户自动获得该 Path；移出后只撤销来自该组的权限。
- 撤销组授权不影响其他组或单独授权；同一 Path 在客户端只出现一次。
- 首期组不嵌套，不按标签自动选成员，不带拒绝规则，也不增加组级配额、倍率或出口覆盖。

示例：Alice 获授“香港组”和 A 的单独权限，香港组含 A、B。撤销香港组后 Alice 保留 A，失去 B。把 C 加入香港组，其他仍获授该组的用户自动获得 C。

## 2. 数据模型：保留授权来源

不能只循环调用当前授权接口：`path_accesses` 对 user + path 唯一，没有组来源；复制授权无法正确处理重叠撤权。

保留 `path_accesses` 作为有效授权投影，拟新增：

| 表 | 职责 | 唯一关系 |
| --- | --- | --- |
| `path_groups` | 名称、说明、启用状态、revision、归档状态 | 活动名称唯一，身份使用 ID |
| `path_group_members` | 组成员及顺序 | group_id + path_id |
| `user_path_group_grants` | 用户组授权及启用/撤销状态 | user_id + group_id |
| `direct_path_grants` | 单独授权来源及启用/撤销状态 | user_id + path_id |

组来源由成员关系与组授权联结得出，不再保存逐用户、逐成员的组来源副本。有效集合是直接授权与有效组授权展开后的并集，再套用现有用户、线路、节点、到期和禁用条件。组授权不能绕过管理禁用，也不能在后台重算时恢复被安全撤销的凭据。

对 user_id + path_id 去重后维护 `path_accesses`。订阅、发布、影响预览和凭据清理使用同一个 db facade 计算规则，不能只有 UI 支持组权限。所有旧授权写入入口改为修改来源，再重算投影，投影不接受独立编辑。

## 3. 变更、事务和并发

组授权、批量修改成员、撤销组授权、组暂停/归档通过同一事务执行：

1. 校验预览版本，计算受影响用户和变更后有效 Path 集合。
2. 检查全部用户的发布名称、链可解析性、资源状态及批量限制。
3. 更新来源，重算有效授权投影。
4. 为新增的可选根 Path 及全部 dialer 链确保 node binding 和 ProxyCredential。
5. 根据变更后全部有效 Path 的链闭包清理不再需要的技术凭据。
6. 同时提交来源、投影、技术资源和审计记录；失败全部回滚。

现有 `GrantPathToUser` 分步创建技术资源，应先提取可复用的事务内函数，不能直接循环调用会自行提交的 public 方法。撤销也不能逐个调用无条件软删有效 PathAccess 的旧方法。

同一 Proxy 被多条有效 Path 使用时复用凭据，不因某个来源移除而禁用。重新授权涉及已撤销凭据时，沿用现有新密钥与显式恢复流程，不能恢复泄露过的旧密钥。用户禁用、节点暂停等状态不得被组变更解禁。

首期同步处理有界批量：G0 确定并验证成员数、受影响用户数和预览大小上限，超限明确拒绝。暂不采用异步最终一致撤权，避免故障期间留下有效权限。

影响预览带组 revision 及相关授权/成员版本；提交时事务内校验并重算。预览后其他组授权、直接授权或链依赖变化，也应使原预览失效，不能只校验组名。

## 4. 生命周期和隔离边界

- 仅可选 `selectable` 根 Path 加入组；`dependency` Path 按链闭包提供技术权限，不自动成为可选线路。
- 组可跨节点、协议；界面列出受影响节点，不能假定发布单个节点即全部生效。
- 暂停组保留成员和授权来源，期间不贡献权限；恢复是显式操作，重新预览与验证。
- 暂停 Path 可保留成员关系并显示不可用；组重算不重新启用它。
- Path 删除或 Node/Proxy 删除导致退役时，在现有删除事务中归档或移除相关成员与直接来源，重算投影和凭据。删除预览增加受影响组及用户。
- 新建同名 Path、Node、组或用户使用新 ID，不继承历史关系；旧资源不因同名资源出现而复活。
- 归档组只收回这个来源的权限，不删除 Path；保留历史和操作记录。用户删除时撤销其直接及组来源，防止重算复活授权。

用户界面的“撤销单独授权”只移除直接来源；仍来自组时显示具体组名。首期不支持“用户保留某组，但排除其中一条线路”，避免引入隐式拒绝优先级。

组是管理授权的工具，不是新协议隔离边界。多个 Path 可能复用同一 ProxyCredential；移除某条 Path 能取消其发布，但不能保证已经获知同一入口凭据的客户端无法通过另一 Host 连接。技术凭据是否保留取决于用户是否仍需该 Proxy；更细隔离需要独立入口或凭据设计。

## 5. 发布和生效

授权事务提交后，订阅生成读取新的有效集合；客户端仍需刷新配置。节点技术权限继续通过现有配置预览和发布流程下发，不因保存组隐式重启 sing-box。

分别展示“授权已保存”“待发布节点”“节点已应用”。撤权不承诺立即终止已有连接；未应用时不能宣称运行配置中的凭据已移除。跨节点发布部分失败应显示尚未收敛的节点。

首期不自动生成客户端 selector，也不改变 Mihomo dialer-proxy 链。按组输出客户端选择菜单是独立展示需求，授权组本身不决定客户端路由。

## 6. API 与界面

拟议 admin API，均使用 ID 并遵守现有认证和错误约定：

| 接口 | 用途 |
| --- | --- |
| `GET/POST /api/admin/path-groups` | 列表和创建 |
| `GET/PATCH/DELETE /api/admin/path-groups/{id}` | 详情、修改及归档 |
| `PUT /api/admin/path-groups/{id}/members` | 带 revision 替换有序成员集合 |
| `POST /api/admin/path-groups/{id}/impact` | 成员、状态及归档变更预览 |
| `PUT/DELETE /api/admin/users/{id}/path-groups/{groupID}` | 幂等授权/撤销，验证影响 |
| `GET /api/admin/users/{id}/effective-path-accesses` | 有效线路和全部来源 |

现有单独授权、兼容 proxy-grant、managed Path 自动维护和删除入口全部接入来源模型，不留下绕过投影计算的写入路径。

界面包括组列表/详情、批量选 Path、用户“授权组”和“单独授权”，以及有效线路的来源展开。预览显示新增/失去权限人数、由其他来源保留的权限和受影响节点。成员数、可用线路数、有效获授用户数分别标注，使用原生 Kumo 和现有表单、表格及 Query 库。

## 7. 实施与验收

1. **G0：来源与事务。** 追加迁移，把现有未撤销 PathAccess 迁为直接来源，保留启用状态，不恢复历史撤权；盘点全部写入入口并提取事务内函数。
2. **G1：有效权限。** 组 CRUD、成员、组授权、原子重算、影响预览；保留计费身份。
3. **G2：界面与灰度。** 来源展示、批量操作和发布状态，一个测试组先行验证。

必须验证：

- 两组与直接授权重叠，撤销任意来源不误收回其他权限，客户端不重复。
- 成员增删动态影响已获授用户；组归档正确清理，无其他来源的权限不残留。
- 多跳共享凭据、发布名称冲突和事务中途故障，来源/投影/凭据正确回滚。
- 禁用、到期、删除、同名重建和安全撤销不造成旧授权复活。
- 并发编辑及旧预览被拒绝；验证批量上限和 SQLite 写事务耗时。
- 新旧单独授权 API、兼容接口和 managed Path 行为一致，迁移前后有效集合与技术凭据需求不变。
- 多节点发布部分失败、客户端未刷新时正确显示生效状态。

DB/API/renderer 测试使用临时 SQLite；前端覆盖来源与预览。实现的验证包括 UI build、Go tests/vet 和 Playwright 页面及移动端检查；真实节点推广与发布仍由部署流程执行。

## 8. 与出口策略的关系

Path 组回答“可以使用哪些线路”，出口策略回答“用户在某个节点上的连接从哪里出去”。首期保持独立；组不覆盖出口，不因 Path 属于多个组产生出口优先级冲突。

“IPv6 线路组”的名称不等于强制 IPv6。实际约束仍须由服务端可识别身份的出口策略实现；按 Path 选择不同出口仍受共享凭据限制。
