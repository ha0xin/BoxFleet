## 事件与日志

### 统一连接记录，切换新日志记录器

实现：Logs 已统一两种来源，连接流新 agent 按单连接保存，来源区间避免重复统计。待部署并逐节点启用、核验采集；旧 agent 和已有聚合历史不会自动变成单连接明细。

- 移除按采集来源命名的 `Connection stream` Tab，新连接流记录统一进入 Network Events 的 Logs。
- 以单条连接为保存和展示单位，取消当前写入前的 5 分钟聚合。
- 连接历史记录可按维护需要清理，清理后执行 SQLite 空间回收；保留用户流量账本、计数器状态及其他关联数据，并核验数据完整性。
- 同一连接的 NEW / UPDATE / CLOSED 关联到同一条连接记录；不把每次 UPDATE 都当作一条新连接。
- 旧日志来源缺少的字段显示 `—`，不补成零，不因字段不足另设页面。
- 图表可在查询时按时间聚合，但不得因此丢弃逐连接明细。
- 迁移期间明确每个节点的主采集来源，避免日志采集与连接流重复统计。

### 旧来源退出与清理（后续）

用户决定：所有节点完成 sing-box 1.14 升级后，删除旧网络日志。

实施时需先确认所有受管节点已完成升级，且连接流采集已启用、持续正常上报；仅升级版本不代表新来源已工作。

此处的清理对象是被替代的旧网络日志来源及其历史数据：旧日志解析产生的连接记录，以及若仍有保存的对应原始网络日志。保留新的逐连接记录、System Logs 和现有用户流量计数数据。具体表、保留范围、备份与删除步骤在届时的迁移方案中列明，当前不执行删除。

旧采集路径在迁移期继续工作；停用和移除安排在上述切换条件满足后。

## 分析与可视化

**延期**：不纳入当前 UI 和 sing-box 1.14 升级范围。

目标：参考 Cloudflare 的分析体验，能够查看每个用户的流量分布，以及流量来源和目的地的国家分布。

届时细化：

- 用户维度：总量、上传/下载、趋势、连接数，并可下钻到单个用户。
- 目的地维度：域名、IP、国家/地区的流量排名和占比，以及随时间变化的分布。
- 来源维度：来源 IP、国家/地区的流量排名和占比，以及用户之间的分布。
- 筛选与联动：时间范围、用户、节点、来源、目的地、协议；点击图表或排名项筛选连接明细。
- 地理归属：届时选择 GeoIP 数据源和更新机制；无法定位、私网地址和未知地址单独归类。国家信息是 IP 地理估计，不能当作用户真实位置。
- 数据口径：现有 V2Ray 计数器继续承担用户计费/权威总量；连接流承担来源、目的地等维度的流量分析。区分用户归属率与采集完整性，不把两者混为一个“覆盖率”。

当前不实施以上 Traffic 分析，不增加国家分布字段、GeoIP 依赖或统计接口。存储、查询性能、保留周期及指标展示在后续专门设计中确定。

## 资源生命周期与身份

- 资源的身份和关联由不可变 ID 决定，名字是可修改的标签；未删除资源避免重名，删除后名字可复用。
- 删除节点保留历史、撤销旧 token、归档所属 Proxy；重新接入必须创建新节点、新 ID、新 token，不继承旧 Proxy/Path、流量或升级任务。
- 用户和 Proxy 的历史名字不占用新资源的名字；恢复历史资源时不能覆盖同名活动资源。
- 批量升级的未领取任务等待 10 分钟后取消并跳过；服务端后台推进，不依赖浏览器保持打开。实际执行失败仍暂停供检查。
- 删除 Node/Proxy 时原子处理 Endpoint、递归依赖的 Path、PathAccess 和不再需要的连接密钥；保留历史 ID 和流量账本。
- Node/Proxy/Path/User 删除确认框展示受影响的资源及结果，使用原生 Kumo 表格并适配窄屏；依赖变化时重新确认，被引用的 Path 明确阻止直接删除。
